# marusia-d

Демон периферии колонки VK Mini («Маруся», Amlogic A113X, mainline 6.18 + Alpine/OpenRC):
состояние MPD + сенсорная панель → световое кольцо, панель-часы, автояркость.

## Периферия и интерфейсы (из device tree + stock-прошивки)

| Что | Железо | Как управляется |
|---|---|---|
| Кольцо | 12× WS2812-подобных, SPI0 | `/dev/spidev0.0`, 3.35 МГц, 4 SPI-бита на бит WS2812 (0→1000, 1→1110), GRB, reset 128 байт ≈300 мкс |
| Сенсоры | Hynitron CSK05T, I2C @0x15 | evdev `/dev/input/event0`, keycodes 114, 115, 248, 148, 582 (из DT keys@15) |
| Панель-часы | IS31FL3236A, I2C @0x3C | seg-led класс: `linedisp.*/message`, `map_seg7` (глифы лиц в 'a'..'h', один раз на старте), colon = leds, яркость на родителе, `current_divider` 1–4 |
| Датчик света | Rohm BH1730, I2C @0x29 | IIO `in_illuminance_input` → множитель яркости кольца 0.15–1.0 |

## Логика

- Панель-часы: время ЧЧ:ММ, при play — лицо wow, при pause — sleepy, потом снова часы.
- Сенсоры: 115 → vol+5, 114 → vol−5 (фидбек — белая заливка кольца на 600 мс),
  248 → play/pause (предположение — сверить `touch-keys` на устройстве!), прочие коды — в журнал.
- Датчик света: EMA по lux → глобальный масштаб яркости кольца.

## Связь с LVA (linux-voice-assistant)

Роли перевёрнуты относительно upstream: **слушает колонка** (`:6055`),
LVA подключается к ней сам. Колонка не знает адреса LVA и молча работает
изолированно, пока мозг не поднят; на стороне LVA нужен патч (клиент ws
к периферии вместо сервера). Все адреса — в одном месте, в конфиге LVA:

    LVA → ws://<ip-колонки>:6055

Включено по умолчанию; `marusia-d -lva ""` — полностью выключить.
«Последний побеждает»: повторный коннект LVA выкидывает прежнего клиента.

События → сцены кольца:

| Событие LVA | Сцена |
|---|---|
| `wake_word_detected` | wake — синяя вспышка 0.8 с (LISTEN_RGB) |
| `listening` | listening — синее дыхание |
| `thinking` | thinking — фиолетовое кольцо в пол-яркости + бегущий по кругу диод (оборот 1.2 с) |
| `tts_speaking` | speaking — голубое дыхание |
| `tts_finished` / `idle` | гашение диалога (off) |
| `snapshot` | muted (сцена) + `volume` 0.0–1.0 — синхронизация громкости sink при коннекте |
| `muted true` | muted — тускло-красный статичный (звук мьюта играет LVA) |
| `pipeline_error` | красная вспышка 1.6 с (overlay поверх любых сцен; звук ошибки играет LVA) |
| обрыв связи | noconn — тёмно-красное дыхание (после первого удачного коннекта) |
| `media_player_set_volume` | HA-громкость внешнему плееру → sink + отклик + репорт `volume_changed`; событие `volume_changed` демону при внешнем плеере не приходит (свои репорты LVA не возвращает, HA-слайдер идёт инструкцией) — кейса нет |
| `media_player_play` | HA-медиа: `media_url` (строка или список) → очередь mpd заменяется, играем |
| `media_player_pause` / `media_player_resume` / `media_player_stop` | транспорт HA → mpd (`Pause(true/false)` / `Stop`) |
| `media_player_playing` / `media_player_paused` | эхо собственных репортов — игнорируется |

Приоритет сцен: `solid (HA) > noconn > muted > диалог`; вспышки (громкость/wake/ошибка) — overlay поверх всего.

Обратно (сенсорные кнопки): 114/115 — локальный шаг ±10% по sink (`pactl`), реальная
громкость уходит в LVA репортом `volume_changed` (доля визуальной шкалы 0..1; LVA
синкает HA-сущность и репорт обратно не переизлучается), отклик (звук + вспышка
кольца + панель) — сразу, без ожидания. Автономно — то же самое без репорта.

Колонка — **внешний медиа-плеер** LVA: при коннекте демон шлёт
`register_media_player`, HA-команды воспроизведения приходят инструкциями
`media_player_play/pause/resume/stop/set_volume` (обрабатываются mpdLink'ом в
главном цикле). Состояние mpd репортится в LVA (`media_player_state`:
play/pause/stop → playing/paused/idle, дедуп по последнему отрепорченному) и при
каждом новом коннекте — HA-сущность показывает правду. Регистрация умирает вместе
с коннектом; анонсы (`announcement: true`) играются как обычное media.

Громкость DLNA (слайдер контроллера) — через хуки upmpdcli
(`externalvolumecontrol` → `/usr/local/bin/upmpdcli-volhook` → TCP-порт 6056
демона, флаг `-volapi`): master = системный sink PA, mpd-поток громкость не
пишет (`mixer_type "none"` в mpd.conf). Визуальная шкала (кольцо/панель) —
0..100 при физических 0..150% sink.
582 → `start_listening`, 148 → play/pause (mpd), 248 → `mute_mic`/`unmute_mic`
(сверить keycode'и на устройстве!). С `-lva-light` (по умолчанию) кольцо
регистрируется как light-сущность HA (`light.<satellite>_ring`): вкл/выкл и
яркость с RGB из Home Assistant управляют кольцом; эффекты — «Цвет» (solid),
«Пульсация» (дыхание), «Вращение» (бегущий диод), «Огонь» (независимое
мерцание диодов) — все цветом из HA; выкл возвращает управление демону
(диалоговые сцены).

MPD и LVA не фатальны: оба линка переподключаются сами, кольцо честно показывает
состояние (`noconn`) только после первой удачной связи с LVA.

## Сборка

Нужен Go (модуль без cgo-зависимостей). Кросс-сборка в статику под aarch64:

```bash
go test ./...          # энкодер кольца + регресс LVA
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags='-s -w' \
    -o marusia-d .
```

Статический бинарник ~6 МиБ, без зависимостей. Для rootfs-проекта
(mailru-marusia-rootfs) бинарь кладётся в `template/usr/local/bin/marusia-d`
и попадает в образ при очередной сборке; init-скрипт —
`template/etc/init.d/marusia-d` (after mpd pulseaudio).

## Отладка на устройстве

```sh
# фидбек сенсорной панели (сверить keycode'и!)
touch-keys
# эталон кадра vendor-утилиты против нашего:
ringled --dump test
marusia-d -ring-dump ffffff
# вручную:
marusia-d -mpd 127.0.0.1:6600            # все флаги опциональны
```
